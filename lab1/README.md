# СПП — Лабораторная работа 1. Список задач

Веб-приложение на Node.js с **серверным рендерингом**: HTML собирается на сервере шаблонизатором EJS,
данные отправляются обычными HTML-формами (без fetch и клиентских фреймворков).

**Стек:** Express 5, EJS, multer (загрузка файлов), PostgreSQL 16 (в Docker), pg.

## Возможности

- список задач с сортировкой: сначала невыполненные, по сроку;
- создание задачи: название, описание, статус, ожидаемая дата завершения, сразу можно приложить файлы;
- смена статуса прямо из списка и со страницы задачи;
- фильтр по статусу (GET-форма, `/tasks?status=done`);
- редактирование и удаление задачи;
- прикрепление файлов к задаче, скачивание с исходным именем, удаление файлов;
- подсветка просроченных задач;
- валидация на сервере: форма перерисовывается с ошибками и уже введёнными значениями;
- страницы 404 / 400 / 500.

## Запуск

Нужны Node.js 20+ и Docker.

```bash
cp .env.example .env        # если .env ещё нет
npm install
docker compose up -d        # поднимает PostgreSQL на порту 5433
npm run dev                 # http://localhost:3000
```

Таблицы создаются автоматически при старте (`src/db/schema.sql`).
Остановить базу: `docker compose down` (данные сохраняются в volume `pgdata`; `docker compose down -v` — удалить и их).

## Структура

```
src/
  app.js                    — настройка Express, хелперы шаблонов, 404/500
  routes/tasks.js           — маршруты задач: формы → сервис → render / redirect
  routes/attachments.js     — скачивание и удаление файлов
  services/taskService.js   — бизнес-логика и валидация, SQL-запросы
  db/index.js, schema.sql   — подключение к PostgreSQL и схема
  views/                    — EJS-шаблоны (partials, tasks/index, form, show, error)
public/styles.css
uploads/                    — загруженные файлы (в БД хранятся только метаданные)
docker-compose.yml          — PostgreSQL
```

## Маршруты

| Метод | Путь | Что делает |
|---|---|---|
| GET  | `/tasks?status=` | список, фильтр по статусу |
| GET  | `/tasks/new` | форма создания |
| POST | `/tasks` | создать задачу (multipart, с файлами) |
| GET  | `/tasks/:id` | страница задачи |
| GET  | `/tasks/:id/edit` | форма редактирования |
| POST | `/tasks/:id` | сохранить изменения |
| POST | `/tasks/:id/status` | сменить статус |
| POST | `/tasks/:id/delete` | удалить задачу и её файлы |
| POST | `/tasks/:id/attachments` | загрузить файлы |
| GET  | `/attachments/:id` | скачать файл |
| POST | `/attachments/:id/delete` | удалить файл |

HTML-формы умеют только GET и POST, поэтому изменение и удаление сделаны отдельными POST-маршрутами.
После каждого успешного POST сервер делает редирект (паттерн Post/Redirect/Get), чтобы обновление
страницы не отправляло форму повторно.
